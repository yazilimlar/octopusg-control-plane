## What the check actually enforces

It checks the **shape** of a record, never the quality of its prose. It cannot tell whether an
answer is good; it can only tell that the four questions were answered somewhere:

| Question | What must be present |
|---|---|
| Which requirement statuses moved? | a `## Requirements` section, and the ID of every IMPLEMENTED or VERIFIED requirement assigned to that work package |
| What was run? | a `## Validation` (or `## Commands and results`) section that names `npm run validate` |
| What came back? | a result token — `PASS`, `passed`, `fail 0`, or an `n/m` count |
| What is still open? | an `## Open questions` section, which may say "None." |

Ten existing records gained an Open questions section and WP-01 gained a validation heading. The
questions are real ones, not filler: OD-02's missing off-machine recovery copy, OD-03 blocking
connector authorization, OD-04's unconfirmed credential store, the unsourced brand mark, the
single-entry observer allowlist, and the fact that no trust zone permits a production action.

## What v0.2 is, and is not

It is a local, private, read-only workspace over a pinned registry, with a five-kind truth model,
an owner-run Git observer, a typed resource catalog and generated map, freshness and drift, device
and requirement views, a connector framework at level 0, a simulated event inbox, safe open
actions and a simulated action policy.

It is not connected to anything. There is no credential anywhere in the repository, no network
client in the bundle, no Git remote, no provider client, no webhook receiver and no executor.
Every approval and every event in the build is labelled a simulation. `scripts/audit.mjs` proves
the first four of those on every run and has never been loosened.
