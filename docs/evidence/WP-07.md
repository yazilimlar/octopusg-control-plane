## The ceiling, as a tested rule

`maxLevel` is a ceiling set by owner decision, not by code, and three independent things enforce
it:

| Where | What it refuses |
|---|---|
| `loadConnectors` | a connection record above its connector's ceiling; a scope declared for a level above the ceiling; a scope declared for level 0, which needs none; a granted scope the connector never declared; an approved action below level 3; an action on a connector whose ceiling is under 3 |
| `canRaiseLevel` | any raise above the ceiling **even when an owner authorization is present**; a raise to a level the connector declares no scopes for; a raise with no owner authorization recorded |
| the committed file | every connection is level 0 / `REGISTERED`, with no granted scope, no credential and `lastSuccessfulSync: null` |

No connector in this build declares an action at all, so level 3 and level 4 are unreachable by
construction as well as by rule.

## What this package deliberately does not do

- No credential field, no sign-in, no OAuth redirect, no enable toggle, no `test` button that
  works. The owner actions render as disabled controls with the reason attached, and the reasons
  say what is missing rather than promising it soon.
- No network client: `tests/connections.test.ts` scans `src/connections.ts` for `fetch`,
  `XMLHttpRequest`, `WebSocket` and node HTTP imports and fails if any appears. `scripts/audit.mjs`
  continues to prove the built bundle has none.
- No credential-shaped value may enter a connector record: the loader rejects token, key, private
  key, URL-embedded password and e-mail shapes before anything is rendered or persisted.
- `mac-status` records the contract of the WP-03 observer; it does not drive it. `npm run observe`
  is still started by the owner from the command line and is not reachable from this screen.
