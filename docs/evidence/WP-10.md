## Devices view

Built from `config/devices.json` and `config/policy.json`, loaded through the same validators the
observer uses (`loadDevices`, `loadPolicy`), so the screen can only render records that already
passed the rules: no forbidden field, no value shaped like a serial, MAC, IP or a path carrying a
user name, no capability or enrolment on an employer-owned device.

| Device | Ownership / zone | Enrolment | Capabilities | Local observation |
|---|---|---|---|---|
| Owner's Mac | personal / personal | enrolled | `read_git_status` | may observe |
| Personal Windows laptop | personal / personal-later | not enrolled | none | never observed — not enrolled |
| Company laptop | **employer** / employer | not enrolled | **none** | **never observed — employer-owned** |

Beneath it, the action-tier grid renders `config/policy.json` as data: tiers T0–T4 against levels
0–4, each cell answering only "would the policy permit this?". Nothing on the screen executes,
and the level-4 ceiling for T3/T4 is visible as "no" cells (asserted in the browser check).

## Requirements view

`npm run spec:write` now also writes `data/requirements.json`, a deterministic projection of the
ledger; `npm run validate:spec` fails if that file is stale **and** fails if it ever contains a
machine-specific path. The view renders capability → requirements → evidence, then one table per
milestone with the fields the owner asked for. `VERIFIED` is shown as the ledger's own value,
with the note that only the owner sets it at a gate. A requirement with no evidence file yet says
"none yet" rather than implying completeness.

## Safety

- No hostname, user name, serial number, IP, MAC address or machine fingerprint appears in
  either view. The browser check scans the rendered text for `/Users/`, `/home/`, `C:\Users`,
  MAC and IPv4 shapes; `tests/spec-data.test.ts` scans the generated JSON and the device records
  for the same shapes plus credential shapes.
- The only address-shaped strings permitted in the projection are the documented loopback ones
  (`127.0.0.1`, `0.0.0.0`), asserted explicitly.
- No secret value, no absolute user path, no capability expansion: the device records are exactly
  those committed in WP-03, unchanged.
- Great Order LLC remains an owner-confirmed declared entity with no ownership edges; nothing in
  these views creates or implies one.
