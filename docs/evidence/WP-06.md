## Freshness and drift semantics

| State | Reached when | Never means |
|---|---|---|
| fresh | an observation is within its `expiresAt` | — |
| stale | the observation passed `expiresAt` | agreement — `stale` is reported instead of `match` even when the values are equal |
| error | the collector reported an error | drift or agreement; the reason is shown |
| not collected | no observation covers that field | healthy, in sync, or "no drift" |
| unknown | no observation, a failed or blocked collection, or nothing declared to compare | success |
| match | a fresh, successful observation equals the declared value | that the value is correct — only that the two agree at collection time |
| differs | a fresh, successful observation differs | that either side is wrong; neither is assumed correct |

Confidence follows the WP-02 ladder — observed fresh is high, stale drops a step, unknown is
none — and is printed as text, so the reader never has to infer it from colour. Nothing in this
package fabricates live data: no provider status, no uptime, no deployment freshness is invented,
and the recorded v0.1 comparison table is preserved unchanged beside the new one.
