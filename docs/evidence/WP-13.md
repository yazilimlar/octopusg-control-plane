([S7](../sources/S7-2026-09-18-owner-v03-platform-foundation-authorization.md)). WP-13 covers only
the **design and local, inert preparation** of that direction: the ADR, the requirements, the (not

Never list, which this session did not modify and cannot lift from a chat instruction alone
([S7#session-execution-boundary](../sources/S7-2026-09-18-owner-v03-platform-foundation-authorization.md#session-execution-boundary)).

### What was executed

1. **`scripts/audit.mjs` (ADR-0007 Decision §1).** The remote-set check moved from "zero remotes
   only" to "empty, or exactly one `origin`" at an approved URL, with the comparison extracted to
   `scripts/audit-remotes.mjs` (typed via `scripts/audit-remotes.d.mts`) so the four cases —
   empty, approved, wrong URL, extra remote — are unit tested in `tests/audit.test.ts` without
   touching real git state. `npm run validate` passed against the current zero-remote state
   *before* the remote was added (136 → later 4 new audit tests brought the suite from 131 to
   135 passing, 0 failing, audit PASS with 0 remotes).
2. **Private repository created.** `gh repo create yazilimlar/octopusg-control-plane --private
   --disable-wiki`, then verified with `gh repo view … --json visibility,isPrivate`:
   `isPrivate: true`, `visibility: PRIVATE`, confirmed **before** any push.
3. **Remote added.** `git remote add origin` — first at the HTTPS form
   `https://github.com/yazilimlar/octopusg-control-plane.git` (ADR-0007's default/preferred
   form).
4. **Tag created.** Annotated tag `v0.2.0` on `165397c9fb1803f0985e5b9daf603b743f548519` (the
   WP-12 v0.2 acceptance commit).
5. **Push — HTTPS unreliable, SSH used instead.** Repeated HTTPS push attempts left the remote
   confirmed empty each time (`git ls-remote origin` returned nothing after every HTTPS attempt,
   independently corroborated by `gh api repos/.../branches` and `.../tags` both returning `[]`
   while `pushedAt` was nonetheless set — consistent with a push that reached GitHub's edge but
   never completed the object/ref write). The origin was then changed to the SSH form,
   `git@github.com:yazilimlar/octopusg-control-plane.git`, and the push succeeded. **ADR-0007
   Decision §1 was amended** (its own commit, `0b242d4`) to approve both the HTTPS and SSH forms
   of this one repository, recording the reason; `scripts/audit-remotes.mjs` and
   `tests/audit.test.ts` were updated accordingly and CLAUDE.md's exception section was updated to
   match. `npm run validate` was re-run and passed (136/136 tests, audit PASS, "remote set is the
   one approved origin") with the real SSH origin configured.
6. **SHAs verified independently** — see the table below. Visibility re-verified private after the
   push (`isPrivate: true`, `visibility: PRIVATE`).
7. **OG-SEC-008 → VERIFIED, `platform-resilience` → `AVAILABLE`, ADR-0007 → ACCEPTED** (this
   commit). `npm run spec:write` regenerated the derived sections.
8. **CI** — see [CI status](#ci-status) below.

### CI status

The workflow file, `.github/workflows/validate.yml`, only exists on
`octopusg/v0.3-platform-foundation`; it is **not present on `main`** (main is still at the pre-WP-13
v0.1 commit). Its trigger is `pull_request:` (any base) and `push: branches: [main]`. Pushing
`main` did not run it, because GitHub reads a `push`-triggered workflow from the ref being pushed,
and that ref (`main`) doesn't have the file. `gh run list --repo yazilimlar/octopusg-control-plane`
returns no runs. **CI has not run yet** — this is a trigger-scoping gap, not a failing run, and no
push was attempted to force one (this session was told not to push). Opening a pull request from
`octopusg/v0.3-platform-foundation` into `main` would trigger the `pull_request` event using the
workflow as it exists on the PR branch; that is outside this session's currently granted
permissions (`gh pr create`/`gh pr merge` are not in `.claude/settings.json`'s allow list) and is
left to the owner or an explicitly re-permissioned session.
