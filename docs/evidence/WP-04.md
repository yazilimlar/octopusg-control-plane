## Catalog and graph design

Pure derivation from the pinned snapshot and already-validated observations — no network, no DNS,
no provider API, no filesystem discovery, no clock.

| Kind | Source field | Identifier |
|---|---|---|
| repository | `canonical_repo` (SSH or HTTPS parsed to host/owner/repo) | `repository:<host>:<owner>/<repo>` |
| checkout | `intended_local_path`, `current_local_paths[].path`, `git_state.path` | `checkout:undeclared:<path>` |
| domain | `intended_url` (declared), deployment aliases (observed) | `domain:<hostname>` |
| deployment | `production_state.serving_deployment` | `deployment:vercel:<id>` |
| document | the SHA-256-verified build sources | `document:<file name>` |

`<device>` stays `undeclared` because the registry declares paths, not machines, and an
observation records a path, not a device; device attribution is OG-DEV-002 (v0.4). A checkout
becomes `observed` only where an observation covers that exact path with status `ok` — a failed,
stale or differently-pathed observation leaves it `declared`.

Edge types used: `platform_parent`, `consumed_by`, `depends_on`, `successor_of`,
`source_repository`, `checked_out_at`, `deployed_on`, `serves`. **Ownership is `platform_parent`
and nothing else.** A repository declared by more than one product is flagged as shared rather
than turned into an ownership claim, the shared Artemis production host creates `deployed_on` and
`serves` edges but no ownership, and the Artemis / AgoraXAI Atlas peer distinction is asserted
directly: no ownership edge may run from an Artemis row to an Atlas row. Legal entities are not
nodes and never appear as an edge endpoint.

Current derivation from registry v1.6: 38 resources (25 checkouts, 7 domains, 3 documents,
2 repositories, 1 deployment) and 40 edges, with 0 dangling endpoints and 0 duplicates. The eight
declared v0.1 edges are all present inside the typed graph with their v0.1 meaning.
