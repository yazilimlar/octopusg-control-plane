## What was built

`src/truth.ts` (new, pure: no I/O, no network, no clock):

- **Truth states** — the five kinds of S1 plus `unknown` / `blocked`; `truthOfLegacy` documents
  the v0.1 mapping (`observed` → observed, `inferred` → declared, or derived when calculated).
- **Confidence** — derived from truth state and freshness; `downgrade` and `weakest` make the
  ladder explicit. Never authored by a collector.
- **Observation envelope** — `{projectId, field, value, truth, source:{adapter, resource},
  observedAt, collectedAt, expiresAt, status, reason?}`. Provenance is mandatory.
- **Validation** — fail-closed and value-free: unknown fields, unknown adapters, bad timestamps,
  `status: ok` without a value, and any observation claiming `approved` or `executed` truth are
  rejected. `loadObservationFile` throws only for a structurally invalid file, so one bad record
  cannot poison a build; rejections are reported with an index and a reason.
- **Secret rejection before persistence** — `looksSecret` walks strings, arrays and objects using
  the same credential shapes `scripts/audit.mjs` scans for. `scripts/audit.mjs` is unchanged.
- **Freshness at read time** — `readObservation(o, source, now)` returns value, truth, confidence,
  freshness, status and a display state. The snapshot stays byte-deterministic because no clock
  is consulted during the build.
- **Deterministic derivation** — `evaluateDrift(declared, observation, now)` is pure: an absent or
  non-ok observation gives `unknown`; a stale one still compares but is marked stale and loses a
  confidence step. `indexObservations` keeps the newest record per project and field.

Integration (`src/model.ts`, `src/main.ts`, `src/style.css`):

- `Fact` gained optional `truth`, `confidence`, `freshness` and `state`; the v0.1 `kind` is
  untouched, so existing badges and filters behave exactly as before.
- `applyObservations(projects, records, now)` replaces a declared fact only where an observation
  covers that project and field, keeping the declared value in the fact's note. With an empty
  record list it returns the same array, so the default read model is byte-for-byte v0.1's.
- `driftFor(p, registry, observations?, now?)` keeps its v0.1 result and adds a `derived`
  comparison plus `observedSha` only when a `head_sha` observation exists.
- The evidence drawer shows the truth badge and the state line (`Observed …`, `Stale · …`,
  `Error: …`), and each project dialog states `Local observations for this row: Not collected`
  until a collector has run. No view, layout or navigation changed.

`data/schema.json`: `observations` is a required snapshot property; `$defs.observation` now
carries `truth` (new `$defs.truthState`) instead of `evidence`, and `local-git` joins the adapter
list. `$defs.evidenceKind` is unchanged — the v0.1 kinds keep their meaning.

## Open questions

- The observation store is read at build time from a file the owner produces. Where observations
  should live once more than one device writes them (OG-DATA-004) is not decided.
- Confidence is a ladder, not a number the owner has agreed to. If the owner wants different
  weights, they belong in the ledger before anything scores against them.

## Boundaries kept

Local, private, read-only. No dependency added or installed, no connector enabled, no network call
at build time or in the browser, no OAuth, no device agent, no remote, no push, no deployment, no
secret read. The simulated inbox and approval queue still cannot execute anything: an observation
that claims `approved` or `executed` truth is rejected by the validator. The registry lock and the
fail-closed importer from WP-01 are intact.

## Not done on purpose

Freshness badges in the portfolio and matrix views (OG-UI-003, WP-06), the collector that writes
`work/observations/latest.json` (OG-OBS-001, WP-03), the device record (OG-DEV-001) and the
observation-driven drift column (OG-OBS-002). `dist/` on the Mac is rebuilt by `npm run validate`.
