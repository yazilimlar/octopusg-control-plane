## What was built

**`config/policy.json` + `src/policy.ts` (OG-SEC-002).** Trust zones (`personal` observe/T2,
`personal-later`, `employer`, `cloud` — the last three with no local access), levels 0–4 and
tiers T0–T4 with minimum and maximum levels. `evaluate()` answers whether an action *would* be
permitted; it executes nothing. Structural rules that configuration cannot soften: T3 and T4 cap
at level 3, level 4 needs a named fixed template, a non-automatic tier needs a recorded approval,
and a zone with no local access permits no tier at all.

**`config/devices.json` + `src/devices.ts` (OG-DEV-001).** Declared records only — nothing is
measured from a machine. Each device carries an owner-chosen alias, ownership, trust zone,
enrolment flag, capabilities, prohibited operations and an access model. Validation rejects a
forbidden field name (`serial`, `macAddress`, `hostname`, `username`, `ip`, …), any value shaped
like a MAC address, an IP address, an Apple-style serial or a path containing a user name, a
capability or enrolment on an employer-owned device, a capability on an unenrolled device, a
trust zone the policy does not define, and enrolment into a zone that is not an enrolled zone.
`canObserve()` is the gate the observer must pass.

**`config/observe.allowlist.json` + `src/observe.ts` + `scripts/observe.mjs` (OG-OBS-001).**
The shipped allowlist holds exactly one entry, marked `EXAMPLE`: this repository at
`~/Projects/agoraxai/control-plane`. Paths are stored as written, in `~/` form, so no user name
is committed. No discovery, no recursion, no globs. The observer resolves each declared path
canonically and refuses anything else (below), runs the five commands, keeps counts instead of
filenames and names instead of URLs, validates every record through the WP-02 store, and writes
`work/observations/latest.json` (git-ignored, mode 0600) to a temporary file which is then
renamed. `src/main.ts` now passes the loaded observations into `driftFor`, so a collected HEAD
feeds the WP-02 drift derivation; nothing new is rendered yet (that is OG-OBS-002 / OG-UI-003 in
WP-06), so user-visible behavior is unchanged.

## Exact Git commands permitted

```text
git -C <path> rev-parse --show-toplevel     repository root validation
git -C <path> rev-parse HEAD                current HEAD SHA
git -C <path> rev-parse --abbrev-ref HEAD   current branch name
git -C <path> status --porcelain=v1         counts only (staged / unstaged / untracked)
git -C <path> remote                        remote NAMES only — `remote -v` is never run
```

Every call goes through `execFile` with a fixed argument vector (only the path is substituted),
a per-command timeout (default 5 s, capped at 60 s by configuration validation) and the
environment `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `GIT_CONFIG_NOSYSTEM=1`,
`GIT_ALLOW_PROTOCOL=` plus `-c core.hooksPath=/dev/null -c core.fsmonitor=false -c gc.auto=0`.
No hook runs, no fsmonitor starts, no index is rewritten, no protocol is available, and the
command table is asserted to contain none of `fetch, pull, push, clone, checkout, switch, add,
commit, reset, clean, merge, rebase, submodule, ls-remote, archive, stash, worktree`.

## Security and rejection tests

| Refused | Where it is caught | Test |
|---|---|---|
| Path not in the allowlist | nothing but listed targets is ever resolved | an unlisted repository is neither named nor touched (fingerprint equal) |
| `..` in a path | `loadAllowlist` (raw segments, before normalisation) | rejection case |
| Glob characters, relative path, duplicate path, unknown field, missing `productId` | `loadAllowlist` | rejection cases |
| Symlink escape | `resolveTarget`: `realpath` must equal the declared path | `symlink escape` |
| Missing path, not a directory, no `.git`, subdirectory of a repository | `resolveTarget` | `unknown` record with a reason |
| A `.git` pointing at another repository | root check against `rev-parse --show-toplevel` | fake-git fixture returning another root |
| Command overrunning its timeout | `runGit` | fake `git` sleeping 10 s against a 300 ms timeout: error in under a second |
| Employer-owned device, unenrolled device, zone without local access, missing `read_git_status` | `canObserve` | four refusals |
| Machine identifiers in a device record | `loadDevices` | forbidden keys, MAC, IPv4, `/Users/<name>` path |
| Secret-shaped value in any record | WP-02 store, before persistence | WP-02 suite |
| Output path outside `work/observations/` | `writeObservations` | `../escape.json` refused |

- Counts-only status hides which files are dirty. If the owner wants names, that is a new
  requirement with its own privacy position, not a setting.

## Boundaries kept

Local, private, read-only. No dependency added or installed, no network call anywhere, no remote,
no push, no deployment, no credential or environment read, no employer-owned device, no discovery
or recursive scan, no write of any kind into an observed repository, and nothing written outside
git-ignored `work/observations/`. Approvals and the inbox remain simulations: the policy module
decides, it never executes.
